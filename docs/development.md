# Development and deployment

## Fresh checkout

Use Node 24+, npm, and Git. `.nvmrc` selects 24. Native TypeScript execution and `node:sqlite` are used by tests.

```sh
npm ci
npm run build
npm run db:setup
npm run dev -- --hostname 127.0.0.1 --port 5183
```

`db:setup` executes `drizzle/0000_special_steel_serpent.sql` against the **local** built D1 binding. Run it once on a fresh `.wrangler/state`. Replaying CREATE TABLE statements fails. To reset, stop servers, back up needed local data and remove only this checkout's local persistence before initialization. Never run initialization against production.

For the built Worker instead of development/HMR: `npm run start -- --port 5183`. Both use the same local state. Stop one server before reusing its port. Independent browsers/private profiles get separate guest sessions; ordinary tabs in the same profile share a seat.

## Environment

Local gameplay and CI need no production secrets. Microphones require localhost/HTTPS and permission. Direct audio uses STUN; some networks require TURN.

Copy `.env.example` to ignored `.dev.vars`, uncomment `HOLLOW_ICE_SERVERS`, and replace placeholders with provider-issued `RTCIceServer` entries. TURN entries require URLs, username and credential. Wrangler loads this local secret file; restart preview after changes. Use **scoped ICE credentials**, never a provider management API key. Voice browsers necessarily receive connection credentials; a server secret does not hide these from authorized clients. Plan quota monitoring, rotation and revocation. Production credentials are excluded from this repo.

For the built `npm start` preview, Wrangler's config is in `dist/server/`: put its local `.dev.vars` beside that config (`dist/server/.dev.vars`) after building. That directory is ignored and regenerated by builds. Development through the Vite plugin uses the root `.dev.vars`. Keep both out of Git and never copy production credentials into screenshots or reports.

## Verification

```sh
npm test
npm run typecheck
npm run docs:check
npm run build
npx playwright install chromium
```

With the local server running:

```sh
npm run test:api
npm run test:smoke
npm run test:browser
```

Smoke is the short credential-free CI gate. The longer browser suite uses fake microphones and tests voice/reconnect/full matches; network traversal may affect it. For ten clients: `node tests/showdown-browser.mjs --voice-count=10 --base=http://127.0.0.1:5183`.

`BROWSER_PATH` optionally selects an installed Chromium/Edge executable. `TEST_BASE_URL` sets smoke's URL; `--base=...` sets API/full browser URLs. Generated reports/screenshots go to ignored `test-results/`.

## Deployment boundary

This GitHub repository provides source and CI; Actions does **not** deploy the live game. The retained `.openai/hosting.json` contains the existing public Site identity, not a credential. Do not deploy forks into that identity. The deployment owner uses the separate hosting checkout to build/test, push exact source, package, save a version and deploy. Sites provides D1. Runtime secret changes require redeployment. Static-only GitHub Pages hosting cannot run this backend.

## Troubleshooting

- Missing tables: build and initialize the fresh local database; confirm API and setup share the persistence directory.
- Existing tables: initialization already ran; start preview without replaying SQL.
- Missing browser: `npx playwright install chromium`; Linux CI uses `--with-deps`.
- Busy port: stop the old server or set another port and matching test URL.
- Voice failure: check secure context, permission, peer status, network and relay quota. Text play still works.
- Slow first startup: Workers tooling may need initial setup; CI waits for HTTP readiness.
- Windows npm shim error: repair npm on PATH or invoke your installation's npm JavaScript CLI with Node. Do not commit machine-specific paths.
- Vinext is beta: retain the lockfile and verify dependency upgrades.
